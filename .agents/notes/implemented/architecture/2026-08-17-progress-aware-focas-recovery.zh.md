# Agent Note：面向进展感知的 Focas 恢复回合

状态：已实现

[English](2026-08-17-progress-aware-focas-recovery.md) | 中文

## 问题

第一版 Focas 已能识别权限拒绝、假成功和同族重复失败，但其运行时统计单元对长链代码与终端任务过于粗糙。`run_command` 这类宽工具被视为一个贯穿会话的单一族，因此即使两次测试之间已经成功修改代码，累计三次失败仍会触发换框。另一方面，只要工具被映射却没有配置探针，每次成功调用都会被判为 `unverified`，full profile 可能在普通查询、构建和检查命令后持续注入验证提示。这些误触发会占用模型有限的指令容量，也是强提示在 flash 模型上可能回归的重要原因。

实现还存在三个正确性缺口：`carrier_search` 直接调用 `directiveMessage`，绕过部署侧覆写；目标缺失错误地发出通用换框提示而非 `target_missing`；通配模式匹配工具名子串而非完整名称。

## 决策

**恢复以进展为边界形成回合，而不是使用终身累计计数。** 每个能力族同时保存总失败数和连续失败串。该族一次成功会清除本族失败串；被标记为任务进展的成功会清除所有族的失败串和耗尽状态，使正常的“修改代码—重新测试”循环不会被误判。经验提取只读取上一次产生进展的成功之后的当前恢复回合。

**宽工具根据参数划分语义族。** `command_kind` 将终端调用划分为检查、编辑、测试、构建、安装、版本控制变更、服务操作和一般执行；`path_root` 按首个有效路径组件划分文件写入。彼此无关的失败不再共同触发一次换框。

**验证成为显式策略。** `mapped` 仅在存在探针映射时验证，否则记录透明的 `declared_success`；`required` 使缺少探针的成功保持 `unverified`；`none` 关闭真值源验证。只有独立验证成功才能形成可迁移经验，但部署方标记为状态变更的声明成功仍可重置进展回合。

**完全相同的失败更早熔断。** 归一化指纹消除易变路径、十六进制标识和数字。默认两次相同结果即可提前换框，不同失败仍采用连续三次阈值。

## 影响

Harbor 桥现在按命令类型划分 `run_command`，按路径根划分 `write_file`，对这些通用工具不强制探针，并把成功文件写入视为进展。终端提示被压缩为更具体的动作。空的 provider base URL 会安全回退，长链任务的上下文与输出上限可通过环境变量配置，并采用更大的默认值。验证探针被标记为内部调用，不会递归进入守卫账本；探针异常只形成未确认的证据，并由可配置超时限制时延。

ALE 代理不再按模型共享一个跨任务账本，而是根据模型、系统提示和首个任务消息隔离状态。每条工具结果只处理一次；不活跃会话通过有界 LRU 存储过期；flash 类模型自动选择 lite 提示；HTTP 服务改为多线程，以支持并发评测 worker。

评测启动器不再硬编码 20 题子集。设置 `FOCAS_N_TASKS` 才运行显式冒烟子集，不设置则运行本地完整数据集。`bench-ops/paired_eval.py` 输出配对效应、胜负样本、精确符号检验和配对 bootstrap 区间。

## 备选方案

- **降低全局失败阈值。** 反应更快，但宽工具中的无关失败仍会混合，误触发更多。
- **把每个成功命令都视为进展。** 查询与检查命令会错误清除真实停滞。
- **要求每个写操作都有探针。** 终端和桌面基准不存在统一效果探针，会把守卫变成持续提示噪声。
- **使用模型聚类失败。** 它会给本应稳定模型的机制引入额外成本与方差。当前先采用确定性粗粒度划分和归一化指纹，再依据实测缺口扩展。
