# Agent Note: 封锁守卫 — 被封锁写操作的内置元认知

Status: implemented

[English](2026-08-14-blockade-guard-metacognition.md) | 中文

## 问题

真实的 agent 事后复盘（来源洞察案例：车机桥接 agent）揭示了四种反复被人工提示解开的卡死机制：框架锁定（计划只枚举一个语义族，族外已知路径从不进入搜索）、终止性错误归因（"permission denied"终结调查）、信任声明成功（`ok=true` 被入账而策略层吞掉了写）、缺少切换触发器（同族变体无限深挖）。每次解开 agent 的提示都是可复用的知识——但必须有人提供。缺口是一个运行时层：确定性地发出这些提示、独立验证写操作、并把每次突破内化，让下一个会话更聪明地开始。

## 决策

**新增 `metacog` 包组，含两个包。** `dsh-blockade` 是守卫插件：纯域逻辑（失败形态分类、按独立性分级的判定合成、尝试账本、经验库）加上 Cordis 监听——`tools/post-execute`（经配置的探针工具验证声明写、分类失败、转向）、`tools/pre-execute`（enforce 模式提权拒绝）、`agent/session-start`（经验召回）。`dsh-blockade-sim` 挂载三个确定性封锁世界（忠实于原始案例的车机、Web 后端、托管文件系统）与无密钥实验用的脚本化认知策略。

**六协议是写死的代码，不是提示建议。** 失败形态→下一步动作的映射、"任何不一致即判假成功 / 只有独立级及以上确认才升级声明"的判定规则、换框阈值、吞掉后禁止提权——全部硬编码；模型只会收到规则发出的指令上下文。

**证据按独立性分级。** 与执行器同源的回读（共享写者的状态）可能确认一个从未生效的写——源案例记录过——因此仅有它时保持 `unverified`；任何通道反对即判假；只有 `independent`/`ground_truth` 确认才算验证。

**验证假定写声明其预期可观测效果。** 探针行把探针参数映射到写调用参数（如按键调用携带 `targetVolume`），守卫因此对领域通用：哪个状态该被写移动，由世界而非守卫知道。

**经验在族类层级迁移。** 突破以 `{avoidClasses, workedClass, forms}` 作为仅记日志的 `blockade/lesson` 会话事件提交；部署内后续会话启动时召回匹配经验。族类（`direct_write`、`user_equivalent_input`、`official_entry`……）抽象到足以跨域——车机上的经验把 Web 与文件系统世界的首接触尝试减半。

**实验证据无密钥且可归因。** `examples/blockade-lab` 在两组运行同一脚本策略；被引导组仅增加对指令的服从，因此结果差异归因于守卫。实验场断言每一条预测（基线假成功、引导组零假成功、逐协议消融各自恢复对应机制、经验迁移减半尝试）并在每次运行时重新生成 `report.md`。

## 曾考虑的替代方案

**仅提示的引导（系统提示里列六协议）。** 不采用：复盘显示这些机制恰恰在模型自信地错误的回路中途起作用；建议性散文在最需要转向的时刻与任务焦点竞争，且没有任何东西验证声明成功。

**扩展 `agent-loop` 加入封锁感知。** 不采用：回路是文档化的核心包，仓库惯例是"插件而非回路改动"；所有需要的接缝（`tools/*` 瀑布、`agent/session-start`、`user/message` 上下文）已作为扩展点存在。

**用输出启发式检测静默吞掉（如"SUCCESS 且无 stderr"）。** 不采用：吞掉是声明与世界之间的矛盾，只能经独立通道检测；对声明本身做启发式无法区分真实与被吞的写。

**逐工具自验证（每个写工具验证自身效果）。** 不采用：工具报告自己的成功正是执行器存储失败模式；独立性必须来自写者不拥有的通道，因此验证放在守卫中、探针工具按部署配置。

## 范围与状态

advisory 模式只注入上下文；enforce 模式额外扣留假成功并拒绝吞掉后的提权。经验持久化是进程内的；投影折叠（`goal/change` 模式）暂缓并记录在包 README 的限制中。真模型验证经 `blockade-lab` 示例叶配提供商密钥运行；无密钥套件覆盖转向机制本身。
